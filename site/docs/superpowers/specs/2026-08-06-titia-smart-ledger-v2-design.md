# Titia 小账智能识别系统 V2.0 设计规格

## 目标与约束

把现有“截图/文本生成单笔草稿”升级为本地智能账单解析系统。系统必须保持纯 PWA、本地优先、无登录、IndexedDB 持久化，账单图片不得上传。准确率优先于自动化程度；任何低置信度、多金额、多订单或疑似重复结果都必须进入人工审核，禁止自动入账。

本次是增量升级，不改变天空背景、云朵、圆角卡片、iOS 视觉、底部导航和现有手工记账入口。旧数据必须自动兼容。

## 方案选择

采用“浏览器本地 OCR + 确定性解析管线”。OCR 只提取文字，不直接决定金额和分类。来源识别、金额评分、订单拆分、分类、历史偏好和重复检测分别由独立、可测试的规则模块完成。

本地 OCR 使用懒加载 worker；识别模型作为静态 PWA 资源下载并由 Service Worker 缓存。图片像素只在浏览器内处理。若设备无法加载 OCR，保留粘贴文字入口，仍使用相同解析管线。

## 识别管线

1. 接收一张或多张图片，或直接接收文字。
2. 图片压缩为最长边 1600px 的本地工作副本，保留原图作为待确认附件。
3. OCR 输出按行保留文本和顺序。
4. 来源规则识别微信、支付宝、招商银行、兴业银行、光大银行、淘宝、京东、拼多多、1688、美团、饿了么、滴滴、高德和地铁。
5. 订单分段器根据日期/时间、商户、交易状态、金额锚点与分隔行拆分订单。无法证明分段时保留为一个候选，绝不臆造多笔。
6. 金额评分器生成全部候选：`实付款/实际支付/支付金额/付款金额/扣款金额` 最高，`订单金额/商品金额/合计` 次之；`优惠/减免/红包/余额/累计/总资产` 排除或强降权。最高分与次高分不足安全差值时要求用户选择。
7. 分类器按商品关键词、商户关键词、平台关键词、用户已确认历史记录依次匹配。规则独立存放在 `categoryRules.ts`，只映射到现有分类体系。
8. 重复检测比较日期时间、金额、商户、账户和来源，输出 0–1 相似度。达到 0.78 标记疑似重复，达到 0.9 标记高概率重复；都只提示，不自动拒绝。
9. 生成候选草稿并进入智能审核页。只有用户明确确认的条目才写入真实账单。

## 数据结构 V3

`Transaction` 增加可选兼容字段：

```ts
type Transaction = {
  id: string;
  amount: number;
  type: "income" | "expense";
  category: string;
  subcategory?: string;
  merchant?: string;
  accountId: string;
  date: string;
  source: "manual" | "ocr" | "notification" | "import";
  sourceProvider?: string;
  confidence?: number;
  imageId?: string;
  duplicateCheck?: {
    possible: boolean;
    similarity: number;
    matchedTransactionId?: string;
  };
  note: string;
  reviewStatus: "candidate" | "confirmed";
  createdAt: string;
  updatedAt: string;
};
```

附件使用 Dexie 独立表，避免大型图片进入单一 AppData 状态行：

```ts
type TransactionAttachment = {
  id: string;
  transactionId: string;
  image: Blob;
  createdAt: string;
};
```

数据库升级新增 `transactionAttachments` 表，索引 `id, transactionId, createdAt`。V1/V2 数据读取时通过 normalizer 补全 V3 默认值，不改写用户原始字段。

## 资金一致性

账户显示余额始终定义为：

```text
opening + 已确认收入合计 - 已确认支出合计
```

新增、修改、删除交易都不直接篡改 `account.opening`。删除交易和附件在同一业务操作中完成；交易从集合移除后，派生余额立即恢复。测试必须覆盖消费删除后余额增加、收入删除后余额减少、候选交易不影响余额。

## 智能审核页

审核页显示批次概览与候选卡片。每张卡片支持：选择/取消、收支、金额候选选择、商户、一级/二级分类、账户、时间、置信度、重复提示、查看原图、修改、重新识别和删除草稿。

批量操作支持全选确认、取消全选、删除选中、保存选中。疑似重复项默认不选中；用户主动勾选后才能保存。单条与批量保存都调用同一确认函数。

## 账单列表

已确认交易按本地日期倒序聚合。每个日期只显示一张日期卡片，摘要包含日期、当日支出、收入和笔数；点击展开当天交易。交易行显示分类/子分类、商户、账户、金额和附件入口。删除前确认，删除后同步移除附件并通过派生余额完成回滚。

## 错误与降级

- OCR 未识别到文字：保留图片，提示粘贴文字或重新识别。
- 没有可靠金额：草稿金额留空并阻止保存。
- 多金额接近：展示候选及百分比，必须选择。
- 分类不确定：使用“未分类”，必须人工确认后才可保存。
- 附件存储失败：允许保存账单，但明确提示原图未保存。
- 模型不可用或离线未缓存：不上传图片，降级到文字粘贴。

## 测试验收

单元测试覆盖来源、金额权重、排除金额、十笔拆分、分类优先级、历史匹配、重复相似度和日期聚合。数据测试覆盖 V2→V3、附件 CRUD、删除后的账户余额。组件测试覆盖多金额选择、批量选择/删除、重复提示、确认前不落库、账单日期卡展开和查看附件。

固定验收样例包括：微信支付取实付款；支付宝正确分类；100/优惠20/实付80选择80；十笔文本拆分十条；同一截图再次导入提示重复；删除35.8元支出后账户恢复35.8；同日多笔只渲染一张日期卡。

## 发布与隐私验证

发布前运行 Vitest、ESLint、Vite 构建、390×844 手机视口交互检查和 GitHub Pages `/titia/` 路径检查。网络面板验证图片内容没有请求；线上包确认包含 V3 规则与审核界面。Service Worker 更新后旧 PWA 可获得新版本，原有 IndexedDB 数据保持可读。
