# Titia 时序 PWA 设计规格

## 1. 产品目标与交付边界

Titia 时序是一款温柔、私密、离线优先的个人生活操作系统。正式数据入口为 iOS/iPadOS 17+ 主屏幕 PWA；Safari 页面承担首次访问、安装引导、兼容性提示和备份恢复说明。由于 WebKit 会隔离 Safari 与主屏幕 PWA 的本地存储，本版本不承诺两者共享 IndexedDB，也不建设账号或云同步。

首版完整交付今日、小窝、小账、时光、我呀五个一级模块，以及倒数日、购物、周期、宠物、密码箱、日记、关系、账单、预算、资产、分析、分类和数据管理。所有业务数据来自 IndexedDB，不预置 mock 数据。

## 2. 技术架构

- React、TypeScript、Vite 构建单页应用。
- Dexie 封装 IndexedDB，并提供版本迁移、事务与实时查询。
- React Router 管理页面和可分享的内部路径。
- Service Worker 预缓存应用壳与静态资源，支持离线启动和版本更新提示。
- Zod 校验表单、数据库边界与备份文件。
- React state 仅用于弹窗、表单草稿、导航等临时界面状态。
- 业务写入统一走 feature service；成功提交数据库后，由实时查询驱动界面刷新。

目录按 `app`、`db`、`features`、`components`、`services`、`pwa` 和 `styles` 分层。每个功能域包含模型、仓储/服务、页面、组件和测试，避免跨模块直接操作数据表。

## 3. 视觉与导航

视觉语言由浅蓝天空渐变、柔和云朵、低饱和蓝/粉/薄荷绿、半透明白色卡片、大圆角和轻阴影构成。排版采用适合中文和 iOS 的系统字体栈。界面移动端优先，并适配安全区、横屏和平板宽度。

底部固定五栏导航：今日、小窝、小账、时光、我呀。小窝、小账和时光内部保留参考图中的左侧图标模块栏；主标题、关键汇总卡片和导航固定，长列表在剩余内容区滚动。右下角保留全局蓝色“灵光一闪”悬浮按钮，进入快速备忘录；各页面另提供语义明确的新增按钮。所有新增和编辑表单使用底部抽屉；删除使用带对象名称的二次确认。空状态提供明确的首个操作入口。

参考截图只作为功能描述和交互意图依据，不要求机械复刻旧视觉。新设计保留天气概览、筛选、预算进度、关系双模式、日记心情与宠物功能等信息结构，并重新统一版式、层级与可读性；红色手写批注不进入产品界面。窄屏模块栏压缩为约 72px，内容区不得产生水平滚动。

尊重 `prefers-reduced-motion`，所有交互元素具备可见焦点、语义标签、足够触控面积和对比度。

## 4. 功能设计

### 今日

展示日期、问候语、今日待办进度、最近倒数日、购物清单摘要和当天财务摘要。待办支持新增、编辑、完成、取消完成、删除和截止日期。

### 小窝

- 倒数日：公历或农历日期、每年重复、未来倒计时、过去足迹和按时间排序的统一时间轴。
- 购物：快速录入、想买/已买切换、编辑和永久删除。
- 周期：记录开始与结束日期、自动计算周期天数、展示历史和统计。
- 憨憨：宠物资料、照片成长时间轴、体重与健康记录；图片写入 IndexedDB 前压缩并保存元数据。
- 密码箱：首次设置主密码；PBKDF2 派生密钥，AES-GCM 加密每条凭据。密钥只在解锁会话内存中存在，支持复制并自动清除提示。忘记主密码不可恢复，仅可清空密码箱重新初始化。

### 小账

支持收入、支出、转账，分类管理、月度预算、资产账户、账单列表与分类/月度趋势分析。转账以配对分录维护资产一致性；删除或编辑在事务中同步余额。

为后续自动记账预留：

- 交易字段包含 `source`、`externalId`、`dedupeKey`、`rawPayload`、`confidence`、`reviewStatus`。
- 定义独立 `TransactionImportAdapter`，手工录入只是首个适配器。
- OCR、账单文件、通知识别产生候选交易，确认后才进入正式账本。
- 使用去重键与导入批次避免重复入账，不在本期实现自动识别。

### 时光

日记支持标题、正文、日期、多图、心情标签和筛选。关系记录分为感动瞬间与矛盾复盘，包含关联人物、发生时间、内容、感受、反思与标签，可按人物和类型筛选。

### 我呀

支持本地个人资料、主题偏好、应用信息、存储用量、完整数据导出、导入预检与恢复。恢复支持“覆盖全部”或“合并”，合并采用实体 ID 与更新时间判定，并在提交前展示影响摘要。

## 5. 数据模型

数据库包含 `users`、`todos`、`shopping`、`periods`、`countdowns`、`pets`、`petRecords`、`vaultMeta`、`accounts`、`transactions`、`budgets`、`categories`、`diaries`、`relationships`、`media`、`settings` 和 `importBatches`。

通用实体包含稳定 UUID、创建时间、更新时间和架构版本。图片作为 Blob 独立存储，业务实体仅保存 media ID，便于去重、清理与备份。涉及多表关系的操作使用 Dexie 事务。

## 6. 日期、农历与统计

日期以本地日历日期字符串保存，精确时间以 ISO 时间戳保存，避免跨时区导致生日、周期或账单日期偏移。农历倒数日保存原始农历月、日及闰月标识，每年根据目标年份换算公历日期。不存在的日期采用当年该月最后有效日，并在界面明确提示。

统计从正式交易记录计算，不另存易失的派生总额。资产余额由期初余额与已确认分录计算；预算按自然月和分类聚合。

## 7. PWA、可靠性与错误处理

Manifest 使用 standalone 模式、固定应用 ID、主题色、完整图标和 iOS 元标签。Service Worker 只缓存版本化应用资源，不缓存用户数据库。更新下载完成后提示用户刷新，避免编辑中强制重载。

数据库初始化、迁移、配额不足、图片处理、解密和备份解析均返回可理解的中文错误。表单保留未提交输入，写入失败不伪装成功。应用启动时检测数据库可用性和版本；无法恢复时引导用户导出诊断信息或恢复备份。

## 8. 测试与验收

- 单元测试覆盖日期/农历、周期天数、账务余额、预算聚合、加解密、备份校验和数据迁移。
- 组件测试覆盖主要表单验证、保存、编辑、删除确认和筛选。
- 浏览器端到端测试覆盖五栏导航、离线重载、各模块 CRUD、密码箱锁定/解锁、备份导出/恢复和 PWA 安装资源。
- 使用真实 IndexedDB 测试适配器，不以 React state 或 mock 列表替代持久层。
- 构建产物通过 TypeScript、lint、测试和生产构建；移动端布局在常见 iPhone 视口验证。

验收标准：刷新或关闭后数据仍存在；所有可见主按钮均有实际功能；离线可启动并读写；删除有确认且关联数据一致；空数据库体验完整；不存在展示型 mock 数据；小账模型可无破坏性迁移地增加自动识别适配器。

## 9. 发布策略

生产站点使用 HTTPS、固定同源地址和 SPA 回退规则，确保安装后的 PWA 始终指向同一 origin。发布前运行完整验证并生成生产构建。上线后验证 Manifest、Service Worker、离线启动、图标、安全区与 IndexedDB 持久化。纯本地数据不会随重新部署被覆盖，但用户清除站点数据或卸载相关网站数据会导致丢失，因此设置页持续提供备份提醒。
